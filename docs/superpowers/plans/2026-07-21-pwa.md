# PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make SkillVault installable as a PWA and let the catalog list stay viewable when the local Fastify server isn't reachable — the last piece of the original project scope.

**Architecture:** `vite-plugin-pwa` (Workbox `generateSW` strategy) generates `manifest.webmanifest` and a service worker at build time into `apps/web/dist`. Three icon sizes are pre-generated once from the existing logo via a small `sharp` script and committed to `apps/web/public/`. The service worker precaches the app shell (JS/CSS/fonts/icons) and applies a `NetworkFirst` runtime-caching rule to `GET /api/items` only. No backend changes are needed — `@fastify/static` (already wired in `apps/server/src/app.ts`) serves any file present in `apps/web/dist`, including the new manifest/service-worker/icon files, automatically.

**Tech Stack:** `vite-plugin-pwa` 1.x (Workbox under the hood), `sharp` (one-off icon generation script, devDependency only). No new automated tests — this is browser/service-worker integration behavior, verified manually (same treatment as `launch.vbs`/`stop.bat` in the local launcher plan).

### Task 2: Generate the PWA icons

**Files:**
- Create: `apps/web/scripts/generate-pwa-icons.mjs`
- Create (generated, then committed): `apps/web/public/icon-192.png`, `apps/web/public/icon-512.png`, `apps/web/public/icon-512-maskable.png`

- [ ] **Step 1: Create the generation script**

```javascript
import sharp from 'sharp';
import path from 'node:path';
import { fileURLToPath } from 'node:url';

const __dirname = path.dirname(fileURLToPath(import.meta.url));
const logoPath = path.join(__dirname, '../src/assets/logo-symbol.png');
const outDir = path.join(__dirname, '../public');

// #0f1115 (--color-bg from the dark theme)
const BACKGROUND = { r: 15, g: 17, b: 21, alpha: 1 };

async function makeIcon(size, logoScale, filename) {
  const logoSize = Math.round(size * logoScale);
  const logo = await sharp(logoPath)
    .resize(logoSize, logoSize, { fit: 'inside' })
    .toBuffer();

  await sharp({
    create: { width: size, height: size, channels: 4, background: BACKGROUND },
  })
    .composite([{ input: logo, gravity: 'center' }])
    .png()
    .toFile(path.join(outDir, filename));

  console.log(`Wrote ${filename}`);
}

// 65% fill matches the padded "respiro" treatment approved during brainstorming.
await makeIcon(192, 0.65, 'icon-192.png');
await makeIcon(512, 0.65, 'icon-512.png');
// Maskable icons need extra safe-zone margin so Android doesn't clip the logo
// when applying a circle/squircle mask, hence the smaller 50% fill here.
await makeIcon(512, 0.5, 'icon-512-maskable.png');
```

- [ ] **Step 2: Run the script**

Run: `node apps/web/scripts/generate-pwa-icons.mjs`
Expected: prints `Wrote icon-192.png`, `Wrote icon-512.png`, `Wrote icon-512-maskable.png`, and `apps/web/public/` now contains all three PNG files.

- [ ] **Step 3: Verify the generated files**

### Task 3: Configure the PWA plugin

**Files:**
- Modify: `apps/web/vite.config.ts`

- [ ] **Step 1: Replace the file contents**

```typescript
/// <reference types="vitest/config" />
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { VitePWA } from 'vite-plugin-pwa';

export default defineConfig({
  plugins: [
    react(),
    VitePWA({
      registerType: 'autoUpdate',
      injectRegister: 'auto',
      manifest: {
        name: 'SkillVault',
        short_name: 'SkillVault',
        display: 'standalone',
        start_url: '/',
        background_color: '#0f1115',
        theme_color: '#0f1115',
        icons: [
          { src: 'icon-192.png', sizes: '192x192', type: 'image/png' },
          { src: 'icon-512.png', sizes: '512x512', type: 'image/png' },
          { src: 'icon-512-maskable.png', sizes: '512x512', type: 'image/png', purpose: 'maskable' },
        ],
      },
      workbox: {
        globPatterns: ['**/*.{js,css,html,woff,woff2,png,svg}'],
        runtimeCaching: [
          {
            urlPattern: ({ url }) => url.pathname === '/api/items',
            method: 'GET',
            handler: 'NetworkFirst',
            options: {
              cacheName: 'skillvault-items-cache',
              networkTimeoutSeconds: 3,
              cacheableResponse: { statuses: [0, 200] },
            },
          },
        ],
      },
    }),
  ],
  server: {
    proxy: {
      '/api': 'http://localhost:3001',
    },
  },
  test: {
    environment: 'jsdom',
    setupFiles: ['./src/test/setup.ts'],
  },
});
```

- [ ] **Step 3: Run the full test suite**

### Task 4: Manual end-to-end verification

**Files:** none (manual verification only — service worker/cache behavior is browser integration, not unit-testable, per the design doc)

- [ ] **Step 1: Serve the production build**

- [ ] **Step 2: Verify the manifest and service worker are registered**

Open DevTools → Application tab. Under "Manifest", confirm name "SkillVault", the three icons, `background_color`/`theme_color` `#0f1115`, `display: standalone`. Under "Service Workers", confirm a worker is registered and activated for `http://localhost:3001`.

- [ ] **Step 3: Verify offline catalog viewing**

With the app open and the catalog loaded, stop the server (`stop.bat`). Reload the page.
Expected: the catalog list still renders (from cache). Click into an item's detail page.
Expected: the detail page fails to load data (expected — only the catalog list is cached, per the approved offline scope).

Restart the server afterward (`launch.vbs`) to return to a normal state.

- [ ] **Step 4: Verify auto-update on a new build**

With the app open in the browser and the server running, make a trivial visible change to a component in `apps/web/src` (e.g. temporarily tweak the "Recomendar" nav label), run `rebuild.bat`, then reload the browser tab.
Expected: the new content appears without any "update available" prompt — the service worker updated itself automatically. Revert the trivial change and run `rebuild.bat` again afterward to leave the app in its real state.

- [ ] **Step 5: Verify dev mode is unaffected**

Run: `npm run dev`
Expected: backend (3001) and frontend dev server (5173) start as before, hot-reload works, and no service worker registers (DevTools → Application → Service Workers is empty for `http://localhost:5173`) — confirms the PWA only activates in the production build.
